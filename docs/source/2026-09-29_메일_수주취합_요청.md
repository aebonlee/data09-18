## 요청

기존 과제(선적계획 자동화)의 입력 ①「수주현황」을 만드는 앞단계로 붙인다.

① **건기 (인천 & 군산)**: 파일명에 「납품예정」이 들어간 건기 파일에서 품목코드 · 납품잔량 · 납기일자 수집. 누적결품 건기 파일은 참고자료 → 수집 제외

② **엔진 (인천 & 군산)**: 누적결품(인천&군산) 우선 반영. 파일상 음수 = 고객사 결품일, 납기일 = 결품일 − 2일. 음수 수량은 양수로 전환. 가능하면 작성일자를 발주일자로. 납품예정(인천&군산): 오더유형(V열)에서 Mass PO 제외 후 수주 반영. (결품과 납품예정 중복 처리 규칙은 확인 필요)

③ **발주서 양식 (7개 고객사)**: 각 파일의 괄호 안에 적힌 필요 정보를 읽어 해당 항목만 추출 → 파일마다 열 매핑 정의. 1개 고객사는 PDF → 텍스트 추출 가능 여부 먼저 확인

④ **밥캣**: 밥캣 매크로 생성 로직 문서 참조. 결품현황 = 위블록(누적결품 + 외주 업체 자료) / 아래블록(납품예정 집계, SUMIFS). 직송 시트 투입 순서: 밥캣 일반 → CKD → AM, 외주와 겹치는 일반 행 제외. 원납기를 [오늘 ~ 마지막 날짜]로 클램프, 사내 품번 VLOOKUP·#N/A 매핑 보충. 이번 도구에서는 밥캣 3개 xls를 공통 수주 형식으로 변환하는 것이 목표(매크로 대체 아님, 확인 필요)

⑤ **선적계획**: 품목코드 끝의 (CI) 자동 삭제. 필요 열: 품목코드 · 미판매수량 · 변경선적요청일 (파일명 괄호)

⑥ **공통**: 모든 양식에 수주일자(발주일자) 공통 표시. 결과는 하나의 통합 수주 표: 고객사 · 공장(인천/군산/안산) · 구분(건기/엔진/AM/CKD/밥캣…) · 품목코드 · 수량 · 납기일 · 발주일 · 원본파일. 창고별재고현황(품목코드·합계)은 수주 대비 재고 부족 확인용 조인 후보

## 구현 방향 (정리본)

브라우저 단독(SheetJS), 폐쇄망 모드 기본, 데이터는 로컬에서만. 파일을 한꺼번에 드롭 → 파일명 패턴으로 종류 자동 판별(납품예정/누적결품/직송 × 건기/엔진 × 인천/군산) → 규칙 적용 → 통합표 + 엑셀 내보내기. 판별 못한 파일·열은 「★확인 필요」 리포트로. 먼저 각 원본 파일 머리행 구조를 파악해 기획서에 열 매핑표로 기록.

## 밥캣 매크로 생성 로직 문서에서 이 도구가 참고한 규칙

- 납품예정 4종(일반 / 직송 / CKD / AM) 중 **직송은 매크로에 안 들어가는 작업자 확인용**
- 가공 규칙: 기준일 이전 날짜는 버림, 빈 날짜·칸은 직전 값을 이어 씀, **결품(음수)이 하나도 없는 품번은 제외**
- 직송 시트: 투입 순서 밥캣 일반 → CKD → AM. 밥캣 일반 중 위블록(외주·누적결품) 품번과 겹치는 행은 **통째로 제외**(수량 합산 없음), CKD·AM 은 겹쳐도 전량. 겹침은 품번 문자열이 정확히 같을 때만
- 원납기: [오늘 ~ 결품현황 마지막 날짜]로 조임(과거 → 오늘, 범위 밖 → 마지막 날). 조기납기는 참고, 발주일은 형식만 통일
- 매크로 전용(이 도구는 하지 않음): 사내 품번 VLOOKUP 과 #N/A 매핑 보충, SUMIFS 아래블록, 외부링크 복원·재계산, 오후 추가발주 N회차
